## 1. 概述

### 1.1 背景

团队已经建立了 pytest / Playwright 自动化回归测试套件，但在日常使用中存在以下问题：

1. 测试执行入口分散：有人在本地跑，有人用零散脚本跑，结果靠聊天工具传日志，无法沉淀复用；
2. 只能看到"这一次有没有通过"，无法回答"和上一次相比，是新增了失败、修复了问题，还是老毛病又犯了"；
3. 需要定时执行回归，但引入完整的 CI 平台或商业测试平台成本过高；
4. 测试代码及其第三方依赖直接在服务器上运行，存在安全风险，误操作代价高。

### 1.2 产品定位

qarunner 是一套**自托管、单节点部署的自动化测试执行、调度与回归对比服务**：将团队的测试套件接入平台，按需或定时在隔离容器中执行，自动收集结果并生成报告，并将历次运行结果连成可对比的回归视图。

它不是 CI 平台，不是测试用例管理平台，也不是多租户云服务（边界详见第 7 节）。

### 1.3 产品目标

| 编号 | 目标 | 衡量方式 |
|------|------|----------|
| GO-1 | 套件可接入、可执行 | 新套件从接入到产出首次运行结果，全程在平台内完成，无需修改平台代码 |
| GO-2 | 配置可复用、可定时 | 同一套执行配置可反复触发、可被定时任务引用，到点自动执行 |
| GO-3 | 结果可解释 | 任何一次失败，不离开平台即可定位到具体用例、日志与报告证据 |
| GO-4 | 跨次可对比 | 两次同口径的运行可以区分出新增失败、已修复、持续失败 |
| GO-5 | 默认安全 | 所有测试在隔离容器中执行；任何越权访问被拒绝 |
| GO-6 | 部署简单 | 按部署手册可独立完成单节点部署；可选功能全部关闭时核心功能不受影响 |
| GO-7 | 结果可信 | 失败可归因（新增、修复、持续、不稳定），无对比基准时不给出误导性结论 |
| GO-8 | 失败主动可达 | 登录首页即可看到失败情况；配置通知后失败主动推送 |

运营层面的观察指标（通过率、平均运行时长、运行量、周活跃触发人数、失败后修复尝试率）的计算口径与目标值由质量度量文档单独维护。

### 1.4 本期范围

| 范围内 | 范围外 |
|--------|--------|
| 套件接入、测试执行、定时调度、报告与日志、回归对比 | CI 流水线、用例库与缺陷管理 |
| 账号体系与数据权限、Web 控制台、开放 API | 多租户、组织/项目空间 |
| 可选功能：飞书通知、AI 失败诊断 | AI 自动修改代码、多副本高可用 |

## 2. 用户与使用场景

### 2.1 用户角色

| 角色 | 主要工作 | 权限 |
|------|----------|------|
| 测试/开发人员 | 接入套件、维护执行配置、触发或定时运行、查看结果 | 仅能管理自己名下的资源 |
| 管理员 | 账号管理、存储清理、全量数据查看、故障排查 | 全局权限 |
| 运维人员 | 部署、备份、环境配置 | 部署层面操作，应用内使用管理员账号 |
| 外部系统 | 通过 API 集成 | 与所属账号权限一致 |

### 2.2 核心使用场景

**场景一：提交前验证。** 开发人员改完代码，在平台上对相关套件发起一次即时运行，几分钟内通过实时日志和结果汇总确认改动没有破坏已有功能，再提交合并。

**场景二：每日回归守护。** 测试负责人为核心回归套件配好定时任务，每天凌晨自动执行。早上打开平台首页，通过与昨日结果的对比直接看到：哪些失败是新出现的、哪些已经修复、哪些一直在失败、哪些用例反复不稳定。

**场景三：失败排查。** 某条用例失败后，相关人员在运行详情中查看日志、报告和截图等产物，追溯该用例的历史表现判断是否为不稳定用例，必要时使用 AI 诊断获取根因分析建议。

## 3. 术语说明

| 术语 | 含义 |
|------|------|
| 套件（Suite） | 接入平台的一组测试代码，来源为 Git 仓库或本地目录 |
| 凭证（Credential） | 用于访问私有 Git 仓库的令牌 |
| 执行配置（Profile） | 保存下来可复用的一组运行参数（套件、测试框架、筛选范围、环境变量、超时等） |
| 运行（Run） | 一次异步的测试执行及其全部结果 |
| 调度（Schedule） | 定时规则（cron 表达式 + 时区）与执行配置的绑定 |
| 终态 | 运行的最终状态：完成、失败、超时、已取消；进入终态后不再变化 |
| 同口径 | 两次运行的执行配置、套件、测试框架与运行参数完全一致，此时二者才具备可比性 |
| 基线 | 与本次运行同口径、状态为"完成"的最近一次历史运行，作为对比基准 |
| 不稳定用例（flaky） | 近期结果在"通过"与"失败"之间反复翻转的用例（近 4 次以上观测中翻转不少于 3 次，阈值可配置）；单纯的一次失败或一次修复不算 |

## 4. 功能需求

优先级定义：**P0** 核心主流程与安全底线，缺失则产品不可用；**P1** 完整产品应具备；**P2** 增强能力，可关闭或降级。

### 4.1 测试套件管理

用户将测试代码接入平台形成"套件"。支持两种来源：从 Git 仓库克隆（支持私有仓库），或关联服务器本地目录（适用于受信内网环境）。接入后可浏览套件文件树、按文件或标记筛选要执行的用例，可拉取更新和安装依赖。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| SU-1 | 套件列表 | P0 | 登录后可查看可执行的套件集合 |
| SU-2 | Git 接入 | P0 | 合法仓库接入成功；非 https 或 git 协议形态的地址一律拒绝 |
| SU-3 | 本地目录接入 | P1 | 平台可见范围内的既有目录接入成功；路径不存在时明确报错 |
| SU-4 | 套件更新 | P1 | 仅所有者或管理员可操作；更新后内容变化可见；失败明确报错 |
| SU-5 | 依赖安装 | P1 | 对声明了依赖的套件执行安装；失败必须明确报告 |
| SU-6 | 文件与标记筛选 | P1 | 选定文件或标记后，实际执行范围与选定范围一致 |
| SU-7 | 套件删除 | P1 | 仅所有者或管理员可操作；删除后不可见 |
| SU-8 | 路径安全 | P0 | 含路径分隔符或以点号开头的套件名一律拒绝；无法通过恶意路径访问未授权内容 |

**业务规则**

- 普通用户不得对他人名下的套件执行运行、更新、依赖安装或删除；管理员不受此限。
- 本地目录接入默认部署环境受信：登录用户对平台可见的目录范围视为同等可信；部署时应据此收敛目录挂载范围，无法接受时应仅使用 Git 接入。

### 4.2 访问凭证管理

用于接入私有 Git 仓库。凭证一经保存即加密存储，任何查询接口不返回明文；克隆和拉取时安全注入，不出现在命令行、地址栏或日志中。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| CR-1 | 保存访问令牌 | P1 | 加密存储 |
| CR-2 | 密钥不回显 | P0 | 任何接口响应不包含密钥内容 |
| CR-3 | 安全注入 | P0 | 密钥不出现在命令行参数、URL 与平台日志中 |
| CR-4 | 权限隔离 | P0 | 无法使用他人的凭证 |
| CR-5 | 删除保护 | P1 | 删除仍被套件引用的凭证后，相关套件更新明确失败，不静默改为匿名拉取 |
| CR-6 | 凭证更换 | P2 | 通过"删除后重建"完成更换，操作路径有文档说明 |

### 4.3 执行配置管理

将一组运行参数（套件、测试框架、筛选范围、附加参数、环境变量、超时时间）保存为可复用的执行配置，支持一键触发和被定时任务引用。可为配置设置飞书通知地址。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| PF-1 | 配置增删改查 | P0 | 所有者可管理；他人不可读写 |
| PF-2 | 一键触发 | P0 | 基于配置创建的运行与该配置正确关联 |
| PF-3 | 通知地址设置 | P2 | 仅接受 https 地址；指向内网或本机的地址拒绝保存 |

**业务规则**

- **删除执行配置将连带删除其名下全部定时任务**；界面与 API 文档必须明确提示该后果。

### 4.4 测试运行

用户基于执行配置一键发起运行，或直接填写参数即时发起。运行为异步执行：提交后系统立即受理，运行经历"排队中→执行中"，最终进入完成、失败、超时或已取消之一的终态。**所有测试统一在隔离容器中执行**，测试代码不在服务器进程中直接运行。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| RN-1 | 异步执行 | P0 | 提交即受理；具备排队、执行中状态；最终进入唯一终态 |
| RN-2 | 即时运行 | P0 | 无需保存配置即可发起；危险参数与路径被拒绝 |
| RN-3 | 容器化执行 | P0 | 全部运行在隔离容器中执行（隔离要求见 5.1 节） |
| RN-5 | 双框架支持 | P0 | pytest 与 Playwright 均产出用例级结果；Playwright 产物可在平台内获取 |
| RN-6 | 取消运行 | P0 | 取消后进入"已取消"终态；执行环境终止，并发额度释放 |
| RN-7 | 重跑 | P1 | 按原参数创建新运行；原记录不变 |
| RN-8 | 全局并发控制 | P0 | 同时执行数不超过上限（默认 4，可配置）；达到上限后新运行排队等待，不丢弃 |
| RN-9 | 单用户配额 | P0 | 单个用户在途运行超过上限（默认 20，可配置）时拒绝并提示；管理员不受限 |
| RN-10 | 超时控制 | P0 | 单次运行超时可配置（默认 30 分钟，单次上限 24 小时）；超时后进入超时终态 |
| RN-11 | 运行查询 | P0 | 列表与详情包含结果汇总、状态、起止时间、日志尾部；遵循数据权限 |
| RN-12 | 运行锁定 | P1 | 锁定的运行不被清理任务删除 |
| RN-13 | 删除运行 | P1 | 彻底删除记录与产物；在途或已锁定的运行不可删除 |
| RN-14 | 产物清理 | P1 | 管理员按保留期清理过期产物；已锁定的不清理；运行记录本身保留 |
| RN-15 | 异常恢复 | P0 | 服务重启后：执行中的遗留运行标记为失败，排队中的自动继续执行，不存在永久"进行中"的记录 |
| RN-16 | 优雅停机 | P1 | 停机设有缓冲期（默认 30 秒）；缓冲期内完成的运行数据完整；超出缓冲期的在途运行以终态收敛 |

**业务规则**

- 运行使用发起时刻服务器上的套件内容，平台不会自动拉取最新代码；需要更新时应先执行套件更新（SU-4）。定时任务同样遵循此规则。
- Playwright 的结果与产物目录由平台统一管理，用户参数不得将产物写出平台管理范围。

### 4.5 结果、报告与日志

运行结束后可查看结果汇总（通过/失败/跳过/错误数量、耗时、通过率）与 HTML 报告；执行过程中可查看实时滚动日志；运行产生的截图、录屏等产物可在线浏览和下载。每条用例的结果单独入库，作为回归对比的数据基础。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| RP-1 | 结果汇总 | P0 | 运行结束后可查看各状态数量、耗时与通过率 |
| RP-2 | 用例级结果入库 | P0 | 每条用例的名称、状态、耗时、错误信息逐条持久化 |
| RP-3 | HTML 报告 | P0 | 报告组件可用时正常查看；不可用时明确提示，不影响其他功能 |
| RP-4 | 实时日志 | P0 | 执行中流式输出；日志总量有上限（保留末尾 5 万行），防止存储无限增长 |
| RP-5 | 运行产物 | P1 | 可列出、下载、打包；不可访问该运行目录之外的内容 |
| RP-6 | 首页失败可见 | P1 | 登录首页直接呈现失败与活跃统计，无需翻查列表 |

### 4.6 回归对比（核心功能）

将历次运行结果连成回归视图，回答"和上次比有什么变化"。这是 qarunner 区别于普通测试执行工具的核心能力。

- **基线对比**：将本次运行与最近一次同口径的完成运行对比，失败变化归为五类——新增失败、已修复、持续失败、新增用例、消失用例；
- **通过率趋势**：查看某套件历次运行的通过率变化曲线；
- **不稳定用例识别**：自动标记结果反复翻转的用例（判定标准见第 3 节术语）；
- **用例历史**：查看单条用例在历次运行中的表现序列。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| DF-1 | 基线对比 | P0 | 五类变化正确区分 |
| DF-2 | 仅同口径可比 | P0 | 口径不一致时明确提示"无基线"，不做强行归类 |
| DF-3 | 对比遵循权限 | P0 | 普通用户的基线候选不包含他人的运行 |
| DF-4 | 通过率趋势 | P1 | 仅统计"完成"状态的运行；无数据时返回空 |
| DF-5 | 用例历史 | P1 | 单条用例的历次状态可按时间顺序查看 |
| DF-6 | 不稳定标记 | P1 | 达到判定标准的用例带明确标记；判定阈值可配置 |
| DF-7 | 质量看板 | P2 | 时间窗口内的通过率、时长、运行量、不稳定用例数可视化呈现 |

**业务规则**

- 失败的判定标准全平台统一：用例状态为"失败"或"错误"计为失败，"跳过"不计。
- 无可比基线时必须明确告知"无基线"，禁止把全部用例误报为"新增失败"。
- 不稳定用例的**处置**（修复、隔离、删除）在测试代码中完成；平台只负责识别与展示，不提供用例管理功能。

### 4.7 定时调度

为执行配置设置定时规则（cron 表达式 + 时区），到点自动发起运行；也可跳过等待立即触发一次。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| SC-1 | 调度增删改 | P1 | 非法的表达式或时区不可保存；关联的执行配置必须存在 |
| SC-2 | 触发时间预览 | P1 | 保存前可预览未来数次（不少于 3 次）触发时间 |
| SC-3 | 到点自动执行 | P1 | 仅"启用"状态的调度触发；停用后不触发 |
| SC-4 | 立即触发 | P1 | 产生新运行并归属于触发人 |
| SC-5 | 防重复触发 | P1 | 同一触发时点只产生一个运行 |

### 4.8 消息通知（可选功能）

运行进入终态后向飞书群发送结果卡片。启用条件：部署时配置了平台访问地址，且运行关联的执行配置设置了通知地址；两者任一缺失则通知整体关闭。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| NT-1 | 终态通知 | P2 | 满足启用条件即发送；发送失败或超时不影响运行结果与状态 |
| NT-2 | 可整体关闭 | P2 | 不配置即关闭；核心功能不受任何影响 |

说明：平台首页的失败可见性（RP-6）已保证不依赖外部渠道也能及时发现失败，因此外部推送定位为增强能力。

### 4.9 AI 失败诊断（可选功能）

配置模型服务密钥后，可对失败的运行发起智能诊断：系统聚合失败用例、日志、基线对比与历史表现，产出结构化的根因分析（六类根因之一、置信度、证据与处理建议）。诊断只读取数据，不会修改任何代码。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| AI-1 | 结构化诊断 | P2 | 产出根因分类、置信度、证据、是否疑似回归与建议 |
| AI-2 | 降级保护 | P0 | 未配置密钥或模型调用失败时不产生服务错误，明确提示或给出兜底结果 |
| AI-3 | 无失败不虚构 | P2 | 无可分析内容时明确提示 |
| AI-4 | 调用限频 | P1 | 按用户限制调用频率（默认每分钟 10 次，可配置）；超限拒绝并告知等待时间 |
| AI-5 | 服务商可切换 | P2 | 支持主流模型服务商及自建网关；诊断结果结构不随服务商变化 |

### 4.10 账号、权限与系统管理

平台采用"管理员 / 普通用户"两级角色。数据权限贯穿所有功能：普通用户只能查看和操作自己名下的套件、凭证、执行配置、运行与调度；管理员可跨用户管理。

| 编号 | 需求 | 优先级 | 验收要点 |
|------|------|--------|----------|
| UI-1 | Web 控制台主流程 | P0 | 不写脚本即可完成接入、配置、触发、查看结果与对比的完整流程 |
| UI-2 | 用户管理界面 | P1 | 仅管理员可用：创建用户、改密、调整角色、删除 |
| UI-3 | 多语言与主题 | P2 | 中英文与明暗主题切换在主要页面可用 |
| UI-4 | 键盘可访问 | P2 | 关键操作可全键盘完成；对话框焦点受控 |
| UI-5 | 开放 API | P0 | 与界面同一套权限模型；集成方可完成同等主流程 |
| UI-6 | API 契约文档 | P1 | 提供机器可读的接口描述，与实际行为一致 |
| UI-7 | 健康检查 | P0 | 提供就绪探测接口：数据库可用方为就绪 |

**业务规则**

- 登录采用用户名密码，之后使用令牌或同源 Cookie；禁止以 URL 参数传递令牌。
- 登出、修改密码、角色变更后，该用户全部已发放令牌立即失效。
- 不允许删除自己的账号；不允许移除系统中最后一名管理员。
- 越权访问他人资源时，"无权限"与"不存在"的报错可区分；列表查询只返回本人数据。

## 5. 非功能需求

### 5.1 安全性

| 编号 | 要求 |
|------|------|
| NF-1 | 启动安全门禁：密钥或管理员密码缺失、强度不足或为默认占位值时，服务拒绝启动 |
| NF-2 | 登录防暴力破解：同一"用户名 + IP"连续失败达阈值（默认 5 次）后按指数退避锁定（60 秒起，上限 900 秒） |
| NF-3 | 执行隔离：容器以非特权用户运行、无网络访问、系统权限最小化、文件系统只读、内存/处理器/进程数设有配额；危险参数与路径在创建阶段拦截 |
| NF-4 | 外部地址收敛：Git 地址与通知地址仅接受受控协议形态，指向内网或本机的地址一律拒绝，防止服务器被诱导访问内部资源 |
| NF-5 | 解析防护：测试报告解析防外部实体注入；单报告输入设 10MB 上限 |
| NF-6 | 密钥卫生：凭证加密存储、永不回显、不落日志 |
| NF-7 | 高成本操作限流：AI 诊断与单用户在途运行均有默认限额 |

### 5.2 可靠性

| 编号 | 要求 |
|------|------|
| NF-8 | 服务重启后不存在永久"进行中"的运行（详见 RN-15） |
| NF-9 | 通知、AI 等外部服务故障不影响运行的执行与结果记录 |
| NF-10 | 数据库不可用时健康检查必须报告异常 |
| NF-11 | 停机时为在途任务提供数据保全缓冲（详见 RN-16） |
| NF-19 | 版本升级时自动完成数据库结构迁移；迁移失败必须拒绝启动且不损坏原有数据；不支持版本回退（回退依赖备份恢复） |

### 5.3 性能与容量

| 编号 | 要求 |
|------|------|
| NF-12 | 全局并发数与单用户配额均可配置，且提供安全默认值（4 / 20） |
| NF-13 | 运行日志与 AI 分析输入均有上限截断，防止资源被单次运行耗尽 |
| NF-14 | 产品定位为小团队单节点部署，不承诺大规模集群服务能力 |

### 5.4 部署与运维

| 编号 | 要求 |
|------|------|
| NF-15 | 提供开发、生产两套标准部署路径，按部署手册操作即可完成 |
| NF-16 | 生产环境界面与 API 同域名提供服务 |
| NF-17 | 数据库、产物、套件目录支持整体备份；备份文件不加密，保密性等同服务器文件系统 |
| NF-18 | 全部运行配置通过环境变量管理，配置项清单与默认值以部署手册为准 |

## 6. 约束、假设与依赖

| 编号 | 内容 | 不满足时的影响 |
|------|------|----------------|
| AS-1 | 服务器需具备容器运行环境（**硬性依赖**） | 平台可启动、可查历史，但无法执行任何测试 |
| AS-2 | 按单实例部署设计（异常恢复、调度去重均以此为前提） | 多实例部署不在承诺范围内 |
| AS-3 | 部署环境受信：平台服务持有容器管理权限，服务一旦被攻破等同于取得服务器最高权限；真正的安全边界是执行容器 | 平台暴露于不受信网络时须由网络层另行防护 |
| AS-4 | 浏览器登录要求界面与 API 同域名部署 | 跨域部署时 Cookie 登录不可用 |
| AS-5 | AI 模型服务、飞书、报告生成组件为可选外部依赖 | 对应功能降级或关闭，核心功能不受影响 |
| AS-6 | 服务器时钟与时区数据正确 | 定时任务触发时间不可信 |
| AS-7 | 不稳定用例的修复与隔离在测试代码中完成，平台只识别不管理 | 期望平台代管用例的诉求不在本期范围 |
| AS-8 | 本地目录接入场景下，登录用户对平台可见目录视为同等受信 | 无法接受时应禁用本地接入，仅用 Git 接入 |

## 7. 产品边界（明确不做）

1. CI 流水线：不做代码仓库事件触发、多阶段构建编排；
2. 测试管理平台：不做用例库、测试计划、缺陷管理、需求关联；
3. 多租户：不做组织、项目空间与计费隔离；
4. 高可用集群：默认形态不做多副本部署；
5. 独立命令行工具；
6. AI 自动修改测试代码或业务代码；
7. 完整审计平台与监控指标体系（最小化操作留痕作为候选需求另行评估）；
8. 数据导出与报表专用接口（API 本身返回结构化数据）。

## 8. 风险与对策

| 编号 | 风险 | 对策 |
|------|------|------|
| RK-1 | 不稳定用例的判定阈值为经验默认值，未经真实数据校准，可能误报或漏报 | 阈值可配置；积累数据后校准（见第 10 节） |
| RK-2 | 平台服务持有容器管理权限，服务被攻破即服务器失陷 | 输入面全面防护（5.1 节）；部署于受信内网；残余风险在产品定位内接受 |
| RK-3 | 单节点部署存在单点故障，停机期间定时任务不触发 | 支持整体备份与快速重建；定位内接受 |
| RK-4 | AI 诊断会将失败日志片段发送至外部模型服务，可能包含敏感信息 | 默认关闭；日志截断后发送；调用限频；支持自建网关 |
| RK-5 | 嵌入式数据库在高并发写入下吞吐受限 | 小团队定位内接受；超出定位时另行立项 |
| RK-6 | 通知地址校验不解析域名，指向内网的域名可绕过校验 | 该请求仅发送通知卡片且不回显响应；解析级校验列为候选加固项 |
| RK-7 | 测试代码可能将密钥打印进日志与产物，并随备份扩散 | 访问受数据权限控制；平台不承诺自动脱敏，需团队规范约束 |
| RK-8 | 除登录日志外，删除、清理等敏感操作暂无操作留痕 | 最小化操作审计列为候选需求（见第 10 节） |

## 9. 验收标准

| 编号 | 验收项 | 通过条件 |
|------|--------|----------|
| V1 | 核心主流程 | 场景一、场景二（第 2.2 节）可独立完整走通（人工演示 + 自动化端到端测试） |

| V8 | 生命周期与防护 | 取消、重跑、配额、超时、锁定、删除、清理、异常恢复、停机、升级迁移及调度防护的自动化测试全部通过 |
