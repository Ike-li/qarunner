# qarunner 需求文档

## 执行摘要

**产品定位**：qarunner 是一套自托管、单节点部署的自动化测试执行、调度与回归对比服务（完整方向陈述见 [`DIRECTION.md`](DIRECTION.md)）。它面向使用 pytest / Playwright 回归套件的研发团队，解决四个问题：测试执行入口分散、单次结果无法回答"相比上次是否变坏"、缺少轻量的定时回归手段、测试代码在宿主机直接运行带来的安全与稳定性风险。

**核心能力**：

1. **执行**——测试统一在隔离容器中运行，默认最小权限；
2. **调度**——按 cron 定时或手动即时触发，执行配置可保存复用；
3. **报告**——用例级结果、HTML 报告、实时日志与运行产物；
4. **回归对比**（差异化核心）——基线差异分析、通过率趋势、不稳定用例识别、用例级历史。

**明确边界**：不做 CI 流水线，不做用例/缺陷管理平台，不做多租户 SaaS（第 9 节）。

**质量结论**：本基线经产品、研发、QA、安全四角色评审通过（§0.5）；全部功能需求均有验收归属与目标追溯（第 11、12 节）；主要风险 8 项已登记并明确处置立场（第 10 节）。

## 1. 背景与目标

### 1.1 要解决的问题

团队已有 pytest / Playwright 回归套件，但面临以下痛点：

1. 测试执行入口分散（本地机器、零散脚本、即时通讯工具传递日志），结果难以沉淀复用；
2. 只能看到"本次是否通过"，难以判断相对上次是**新增失败、已经修复、还是长期不稳定**；
3. 需要定时回归，又不希望引入完整的 CI 或 QA 平台；
4. 测试代码及其依赖在宿主机直接运行，安全风险与误操作成本高。

### 1.2 价值链与产品目标

回归测试的核心产出是**信号**——"变更之后，既有行为是否仍然成立"。信号必须**可信**（能区分真实回归与噪声）且**被人消费**（看到、解读、采取行动）才产生价值。产品的执行、调度、报告能力生产并呈现信号，回归对比能力将孤立的单次结果连成可信信号，可发现性与通知能力保证信号触达使用者；不稳定用例的检测服务于信号降噪（其处置在测试代码侧完成，见 AS-7）。产品目标沿这条价值链设立：

| ID | 目标 | 合格判据 | 度量锚 |
|----|------|----------|--------|
| GO-1 | 套件可接入、可执行 | 新套件从接入到产出首个终态运行结果，全程在平台内完成，无需修改平台代码（V1） | [`METRICS.md`](METRICS.md) 指标 #4 平均时长、#5 运行量 |
| GO-2 | 配置可复用、可定时 | 同一执行配置可反复一键触发、可被调度引用，到点自动产生运行（V1） | 指标 #5 |
| GO-3 | 结果可解释 | 任一失败运行无需离开平台即可定位到用例级失败与日志、报告证据（V1） | — |
| GO-4 | 跨次可对比 | 同范围的两次运行能够区分新增失败、已修复、持续失败，可疑用例可查历史（V2） | 指标 #1、#2 |
| GO-5 | 默认安全 | 唯一执行形态为隔离容器；任何越权访问被拒绝（V3、V4） | — |
| GO-6 | 部署简单 | 按部署文档标准路径完成单节点部署且健康检查通过（V6）；可选能力全部关闭不影响主路径（V5） | — |
| GO-7 | 回归信号可信 | 失败可归因：新增/修复/持续/不稳定四类判定口径明确（§3.3）且不误导（无基线时不强行归类）（V2） | 指标 #2（阈值校准见 OP-1） |
| GO-8 | 信号被消费 | 失败信息主动可达：登录首页即可看到（V1）；配置通知渠道后终态主动推送（V5） | 指标 #6、#7（观察期） |

### 1.3 产品定位（引用方向源）

自托管、单节点的测试执行、调度与回归对比服务。完整表述见 [`DIRECTION.md`](DIRECTION.md)。

### 1.4 范围

| 范围内 | 范围外 |
|--------|--------|
| 套件接入、执行、调度、报告与日志、跨次对比 | CI 流水线、用例库/缺陷管理 |
| 账号与对象级权限、Web 控制台与 API | 多租户 SaaS、组织/项目空间 |
| 可选能力：飞书通知、AI 失败诊断 | AI 自动修改代码、多副本水平扩展（默认形态） |

## 2. 使用对象与权限

### 2.1 使用场景与角色

需求的优先级论证以**决策场景**为依据（同一用户可能处于多个场景）：

| 场景 | 要回答的问题 | 依赖的能力 | 关键质量属性 |
|------|--------------|------------|--------------|
| 提交前验证 | 本次变更能否合入？ | 即时触发、实时日志、结果汇总（RN、RP-1/4） | 反馈时长（指标 #4） |
| 套件健康守护 | 回归套件是否仍然可靠？ | 调度、趋势、不稳定检测、基线差异（SC、DF） | 信号可信度（GO-7） |
| 失败排查 | 该失败因何发生？ | 日志、产物、用例历史、AI 诊断（RP、DF-5、AI） | 证据完整性 |

系统权限按**角色**划分（与场景相互独立）：

| 角色 | 典型工作 | 系统权限 |
|------|----------|----------|
| 测试/开发人员（user） | 接入套件、维护执行配置、触发或定时运行、查看结果与对比 | 仅管理本人资源 |
| 管理员（admin） | 账号管理、存储清理、全量数据查看、故障排查 | 全局能力与用户管理 |
| 运维人员 | 部署、备份、环境配置 | 部署层面；应用内使用管理员账号 |
| 脚本/系统集成 | 通过 Token 调用 API | 与对应用户权限一致 |

### 2.2 权限总规则

1. **所有者范围**：普通用户只能读写本人名下对象——套件、凭证、执行配置、运行、调度，及其派生数据（基线差异、趋势、用例历史）。
2. **列表查询**：普通用户仅可见本人资源，不产生错误。
3. **越权访问**：他人资源不可读取或修改；"权限不足"与"资源不存在"的响应可区分（错误码见 API 文档）。
4. **管理员**：可跨用户查看与管理（能力清单见 [`FEATURES.md`](FEATURES.md) 第 8 节：用户管理、产物清理、跨用户查看）。
5. **登录方式**：用户名与密码认证；此后使用 Bearer Token 或同源 Cookie。
6. **禁止事项**：不得以 URL 查询参数携带 Token 作为认证方式。
7. **生产环境**：界面与 API **同源**部署；Cookie 具备 HttpOnly、SameSite=Strict 属性，并在 HTTPS 下开启 Secure。

### 2.3 账号管理

| 能力 | 要求 |
|------|------|
| 登录 / 登出 / 当前用户查询 | 必须具备；Token 有效期可配置（默认 24 小时） |
| 会话失效 | 登出、修改密码、角色变更**必须使该用户全部存量 Token 失效**（旧 Token 后续请求返回 401） |
| 用户增删改（角色、密码） | 仅管理员 |
| 删除本人账号 | 禁止 |
| 移除最后一名管理员（降级或删除） | 禁止 |
| 登录防暴力破解 | 同一"用户名 + IP"连续失败达到阈值（默认 5 次，可配置，0 为关闭）后，按指数退避锁定（60 秒起，上限 900 秒） |

## 3. 术语与核心对象

### 3.1 核心对象

| 对象 | 含义 | 关键关系 |
|------|------|----------|
| 套件（Suite） | 接入平台的测试代码（Git 仓库或本地目录） | 被执行配置、运行引用 |
| 凭证（Credential） | 访问私有仓库的令牌 | 仅元数据可见，密钥不回显 |
| 执行配置（Profile） | 一组可复用的运行配置 | 可一键触发；可被调度引用；可关联通知地址；**删除时连带删除其全部调度（BR-11）** |
| 运行（Run） | 一次异步执行及其结果 | 来源于即时参数、执行配置、调度或重跑 |
| 调度（Schedule） | cron 表达式 + 时区 + 关联的执行配置 | 到点或手动触发产生运行 |
| 用例结果 | 单条用例在某次运行中的结果 | 支撑差异分析、历史、不稳定检测 |

### 3.2 运行状态机

排队中（queued）→ 执行中（running）→ **终态**：完成（completed）、失败（failed）、超时（timeout）、已取消（cancelled，含停机中止的在途运行）。
终态不可取消、不可再变更。

### 3.3 关键术语（判定口径）

| 术语 | 精确定义 |
|------|----------|
| **同范围** | 两次运行的执行配置标识、套件路径、测试框架、编译后参数（标记/选中文件/附加参数在创建时合并入参数串）**四项完全一致**。同一套件同参数下，经执行配置发起与即时发起的运行互不属于同范围 |
| **基线** | 与本次运行同范围、状态为"完成"、创建时间早于本次的**最近一次**运行；不存在时视为"无基线" |
| **失败** | 用例状态为 failed 或 error；skipped 与 passed 不计为失败（差异分析与不稳定判定采用同一口径） |
| **不稳定（flaky）** | 同一用例（套件+名称）按时间序将状态二值化为失败/非失败后：观测次数不少于 4 **且**相邻翻转次数不少于 3（两项阈值均可配置）。单调劣化或一次性"失败后修复"不属于不稳定 |
| **即时运行** | 不经执行配置、直接以参数创建的运行 |
| **在途** | 状态为排队中或执行中的运行 |

## 4. 主路径（必须完整可用）

以下三条为验收底线，细化条目见第 5 节。

### 4.1 首次接入并运行

接入套件（Git 或本地）→ 套件声明了依赖时（如包含 `package.json`）执行依赖准备 → 创建执行配置 → 触发运行 → 进入终态 → 可查看汇总与日志、报告。

### 4.2 日常回归

定时或手动触发同一执行配置 → 与上次**同范围**结果对比 → 区分新增失败、已修复、持续失败 → 可疑用例可查看历史表现。

### 4.3 权限隔离

用户 A 的运行、配置、凭证、对比基线数据，用户 B 不可见、不可用。

### 5.1 套件接入（SU）— P0/P1

| ID | 需求 | 优先级 | 说明 | 合格标准 |
|----|------|--------|------|----------|
| SU-1 | 套件列表 | P0 | 查看可执行的套件集合 | 登录后可列出 |

| SU-4 | 套件更新 | P1 | 拉取 Git 最新内容（复用绑定凭证） | 仅所有者或管理员可操作；更新后套件内容可观察到变化；失败时明确报错 |
| SU-5 | 依赖准备 | P1 | 对包含 `package.json` 的套件执行依赖安装 | 失败必须明确报告 |
| SU-6 | 文件树与标记选择 | P1 | 按文件、pytest 标记 / Playwright 标签筛选 | 选定文件或标记后，运行的实际执行范围与选定范围一致 |
| SU-7 | 套件删除 | P1 | 移除套件 | 仅所有者或管理员可操作；删除后不可见 |
| SU-8 | 路径安全 | P0 | 防目录穿越 | 套件名含路径分隔符或以点号开头的一律拒绝；恶意路径无法访问未授权内容 |

### 5.2 凭证（CR）— P0/P1/P2

| ID | 需求 | 优先级 | 说明 | 合格标准 |
|----|------|--------|------|----------|
| CR-1 | 保存访问令牌 | P1 | 用于私有仓库 | 加密存储 |
| CR-2 | 密钥不回显 | P0 | 查询接口永不返回明文 | 任何响应不包含密钥内容 |
| CR-3 | 安全注入 | P0 | 用于克隆与拉取 | 密钥不出现在命令行参数、URL 与平台日志中 |
| CR-4 | 所有者范围 | P0 | 凭证仅所有者可用 | 无法使用他人凭证 |
| CR-5 | 删除后的引用语义 | P1 | 删除仍被引用的凭证后 | 引用该凭证的套件更新明确失败，不静默降级为匿名拉取 |
| CR-6 | 轮换路径 | P2 | 平台不提供原地更新 | 通过"删除后重建"完成轮换；该路径有文档说明即为合格（人工评审） |

### 5.3 执行配置（PF）— P0/P2

| ID | 需求 | 优先级 | 说明 | 合格标准 |
|----|------|--------|------|----------|
| PF-1 | 增删改查 | P0 | 保存运行配置；删除行为见 BR-11 | 所有者可管理；他人不可读写；删除时连带删除其调度 |
| PF-2 | 一键触发 | P0 | 按配置创建运行 | 新运行关联该执行配置 |

| ID | 需求 | 优先级 | 说明 | 合格标准 |
|----|------|--------|------|----------|

| RN-3 | 容器执行 | P0 | **唯一执行形态**（BR-1） | 全部运行在隔离容器中执行；隔离底线见 NF-3 |

| RN-13 | 删除运行 | P1 | 删除记录与产物 | 在途或已锁定的运行不可删除（返回冲突错误）；删除彻底 |
| RN-14 | 产物清理 | P1 | 管理员按保留期清理 | 非管理员不可执行；仅清理未锁定的过期物理产物，元数据保留 |

| RN-16 | 优雅停机 | P1 | 停机前保全数据 | 停机设有缓冲期（默认 30 秒，可配置）；缓冲期内完成的运行数据一致；**超出缓冲期的在途运行以已取消或失败终态收敛，不得停留在途** |

## 6. 关键业务规则（BR）

以下规则为跨模块强约束，用于消除理解分歧。

| ID | 主题 | 规则 |
|----|------|------|
| BR-1 | 执行形态 | **唯一执行形态为隔离容器**；接口中的执行器字段为兼容保留，不改变实际执行形态 |
| BR-2 | 套件归属 | 普通用户不得对他人名下套件执行运行、更新、依赖准备或删除；管理员不受限 |
| BR-3 | 对比范围 | 仅"同范围"（§3.3）产生基线差异；范围不同即视为无基线 |
| BR-4 | 失败定义 | failed 与 error 计为失败；skipped 不计（差异分析与不稳定判定同口径） |
| BR-5 | 可选能力隔离（P0） | AI 诊断与通知的关闭、失败或超时，**不得**影响测试执行、状态持久化与结果查询 |
| BR-6 | 单节点语义 | 崩溃恢复、调度去重按单实例独占数据库设计；默认不承诺多副本部署 |
| BR-7 | 同源约束 | 浏览器 Cookie 登录仅承诺同源部署形态 |
| BR-8 | 密钥门禁 | 空缺或弱强度的密钥与管理员密码将导致服务拒绝启动 |
| BR-9 | 无基线不误导 | 无可比基线时明确提示"无基线"，不得将全部用例归类为"新增" |
| BR-10 | 套件内容版本语义 | **运行使用触发时刻磁盘上的套件内容，平台不自动拉取更新**；更新须显式执行 SU-4（"调度前自动更新"为开放项 OP-4） |
| BR-11 | 执行配置级联删除 | **删除执行配置将连带删除其全部调度**；由此失去对应定时任务属预期行为，界面与 API 文档须明示该后果 |

### 7.1 安全

## 8. 假设与依赖（AS）

违反下列假设时，产品不承诺对应能力；部署方须自行评估。

| ID | 假设/依赖 | 违反时的后果 |
|----|-----------|--------------|
| AS-1 | 宿主容器运行时可用是**硬性依赖**（唯一执行形态，BR-1） | 平台可启动、可查询历史，但**无法执行任何测试（无替代路径）** |
| AS-2 | 单实例部署（崩溃恢复、调度去重按单实例语义设计） | 多副本部署须自行保证仅一个副本开启崩溃恢复；属超出承诺范围的形态 |
| AS-3 | 部署环境受信：平台服务持有容器管理权限，**平台服务一旦被攻破，等同于获得宿主机管理员权限**；真正的隔离边界是执行容器而非平台进程；平台自身不在宿主进程内运行被测代码（BR-1） | 平台暴露于不受信网络时，须由部署层（反向代理、网络策略）另行加固 |
| AS-4 | 浏览器登录依赖界面与 API 同源部署（BR-7） | 跨源部署下 Cookie 登录不可用 |
| AS-5 | 可选外部依赖按需可达：AI 模型服务（失败诊断）、飞书（通知）、报告生成组件（HTML 报告） | 对应能力降级或关闭，主路径不受影响（BR-5、RP-3） |
| AS-6 | 宿主时钟与时区数据正确 | 定时触发时间不可信 |
| AS-7 | 不稳定用例的**处置**（标记、隔离、重写、删除）在测试代码侧完成；平台仅负责检测与展示，不管理用例（方向边界） | 期望平台代为隔离不稳定用例的诉求见 OP-3（方向级开放问题） |
| AS-8 | 本地目录接入（SU-3）的信任前提：登录用户对平台进程可见的挂载目录树**视为同等受信**；非容器化部署时该范围即宿主文件系统 | 部署方须据此收敛挂载范围；不可接受时应禁用本地接入、仅使用 Git 接入 |

## 10. 风险与开放项

### 10.1 风险登记（RK）

| ID | 风险 | 影响 | 缓解 / 接受理由 |
|----|------|------|------------------|
| RK-1 | 不稳定判定阈值（4 次观测/3 次翻转）为保守默认值，未经真实数据校准 | 误报或漏报不稳定用例 | 阈值可配置；积累生产数据后校准（OP-1） |
| RK-2 | 容器编排信任边界：平台服务持有容器管理权限，等效于宿主机最高权限（AS-3） | 平台服务被攻破即宿主失陷 | 平台输入面全面硬化（NF-3～NF-6）+ 部署面收敛；残余风险在"受信部署环境"定位内接受 |
| RK-3 | 单节点单点故障 | 停机期间调度不触发、结果不可查 | 支持整体备份（NF-17）与快速重建；定位内接受（NF-14） |
| RK-4 | AI 数据外发：失败日志片段发送至模型服务商，可能包含敏感信息 | 数据暴露面扩大 | 默认关闭；日志按上限截断；调用限频；支持自建网关（AI-5） |
| RK-5 | 嵌入式数据库的写并发上限 | 超大团队或高频场景下吞吐受限 | 小团队单节点定位内接受；超出即触发方向级变更（NF-14） |
| RK-6 | 通知地址校验不做域名解析（PF-3/NF-4） | 解析至内网地址的公网域名可通过校验，平台可能被诱导向内网发起请求（服务端请求伪造的残余风险） | 该出网请求仅为发送通知卡片、响应内容不回显；候选加固方案（解析校验与发送前复检）为实现级变更，按 §0.4 评审 |
| RK-7 | 日志与产物可能驻留敏感信息：被测代码可将环境变量中的密钥打印至持久化日志（RP-4）与产物（RP-5），并随备份扩散（NF-17 备份不加密） | 敏感信息驻留与扩散 | 处置立场：**不承诺自动脱敏**；访问由所有者范围权限控制覆盖（§2.2、RP-5）；备份保密性等同部署环境。套件作者须避免打印敏感信息 |
| RK-8 | 可问责性缺口：除登录失败日志外，破坏性与特权操作（用户管理、删除、清理）无操作留痕 | 事后追溯能力不足 | 第 9 节第 7 条排除的是完整审计平台，不排除最小动作审计；候选需求登记于 OP-5 |
