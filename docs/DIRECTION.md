> 版本 **v1** · 拍板日期 **2026-06-30**（决策过程见 [`POSITIONING.md`](POSITIONING.md) §8）。

## 一句话

一个**自托管、单节点的测试执行 + 调度 + 回归对比服务**：把团队的 pytest / playwright 套件接进来，
定时或即席运行（每次跑在硬化的一次性沙箱里），收集结果、生成 Allure 报告，
并把历次运行连成**回归视图**。

## 四支柱

1. **执行** — pytest / playwright × docker（沙箱隔离）。
2. **调度** — cron + IANA 时区，定时或即席触发。
3. **报告** — Allure 报告 + JUnit 解析 + 实时日志（SSE）+ Web 控制台。
4. **回归视图（差异化内核）** — 基线 diff / 通过率趋势 / flaky 检测 / 用例级历史。
   把孤立的单次结果连成时间线，是 qarunner 区别于「跑一次看一次」runner 的核心。

## 边界（刻意不做的）

- **不是 CI** — 无 VCS 集成 / 流水线 / 多阶段构建。
- **不是 QA 平台** — 无用例管理 / 缺陷跟踪 / 需求追溯（所以叫 **runner** 不叫 platform）。
- **不是多租户 SaaS** — 仅用户级 owner-scope。
